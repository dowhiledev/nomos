# Notes on Conceptual Agent
- As now the tool call will be async, i think it is best to consider Agent-Agent communication have a similar async interface to tool calls. Because thats a decision AI make to call another agent.
- We have only Nodes/Steps in the graph. Tools are not nodes. Tools are called by nodes. edges are between nodes (when to transition to the next node/step). : Look into the .old architecture for reference.
- Basically node is a step in the graph.
- Edges define the transitions between nodes. when to go from one node to another.
- Tools are called by nodes to perform specific tasks within itself. (Uses a ReACT style tool calling approach internally)
- compiled graph returns a agent.
- With in a node you can reference another agent as a tool (agent-agent communication)
- Each node can have multiple outgoing edges with conditions to determine which edge to follow based on the decisions made by the node.
- Cycles are allowed in the graph to enable loops and repeated actions.
- Nodes can have parameters that can be configured when creating the graph. (e.g., LLM model settings, tool allowed to use, etc.)
- Globally for every session we will have a global meemory store, LLM Provider.
- But each sub graphs can have their own memory store, LLM provider that overrides the global one (Allows for specialization of sub graphs)
- Agents can run as sessions client side and also server side. (So clients can handle things locally if they want to) - Refer current State approach for this.
